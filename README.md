## 一、这个站解决什么问题

训练一个模型，真正决定成败的往往不是结构图，而是三张表：**数据配比表、训练日程表、失败模式表**。
论文里写的是"我们用了 15T token"，但没人告诉你这 15T 怎么清洗、怎么去重、怎么配比、怎么在
中期做退火、怎么判断一次 loss 尖峰是数据问题还是并行问题。

这个站把七个领域的这些"脏活"拆开讲透：

| 领域 | 核心数据问题 | 核心训练问题 |
|---|---|---|
| MoE | 专家路由与语料领域配比的耦合 | 负载均衡、并行切分、专家并行通信 |
| 多模态 | 图文对清洗、描述重写、交错序列构造 | 三阶段对齐日程、分辨率课程、模态配比 |
| Coding LLM | 代码去重、FIM 变换、仓库级上下文构造 | 长上下文训练、执行反馈、课程编排 |
| RL Post-training | 偏好数据构造、可验证奖励、rollout 采样 | PPO/GRPO/DPO 日程、KL 与熵控制、奖励黑客 |
| 视频生成 | 视频-文本对筛选、镜头切分、时序标注 | 时空 VAE、flow matching、分辨率/时长课程 |
| 图像生成 | 美学过滤、重描述、合成数据配比 | DiT 训练、CFG dropout、蒸馏加速 |
| 音频生成 | 语音/音乐语料、说话人标注、tokenizer 训练 | 自回归+扩散混合、流式训练、码本配比 |

## 四、怎么读

三条路径，按你的时间选：

1. **两小时速览**：领域首页 → 方向地图六条主线 → 每个方向一篇代表论文的第 1、5、7 部分（问题现场/数据管线/失败模式）。
2. **一个周末入门**：故事书（叙事）→ 理论账本前 4 条（把算力账算一遍）→ 算法配方里的 3 个最常用配方（照着跑一遍小规模）。
3. **当手册用**：十二卷全书按主题查；附录的配方速查表和数字反查表用于写方案/评审时核对口径。

每篇文章末尾都有 `对应：papers/xxx · 第 N/9 部分` 的定位行，方便回查与引用。

## 五、技术实现

- **单文件 SPA**：`index.html` 一个文件包含全部路由、渲染、样式；无构建步骤、无框架依赖。
- **按需加载**：`data/manifest.js` 只含领域元数据，每个领域的 `data/domains/<id>/bundle.js` 在进入该领域时才加载。
- **公式**：KaTeX 本地内置（`vendor/katex`），离线可用。
- **图表**：全部为手写 SVG（流程图/对照表/时间线），不依赖外部图片，保证离线与窄屏可读。
- **路由**：`#/<domain>/<page>`，领域内相对链接；阅读进度按领域分别存 localStorage。
- **窄屏**：390px 宽度下无横向溢出（有自动断言）。

```
index.html            单文件应用（路由 + 渲染 + 样式）
data/manifest.js      领域清单
data/totals.js        全站规模口径
data/domains/<id>/    每领域一个 bundle.js（含长文 HTML、题库、故事）
vendor/katex/         KaTeX 与字体
```

本地预览（必须从仓库根目录起服务，否则领域内相对链接会断）：

```bash
python3 -m http.server 8080
# 打开 http://127.0.0.1:8080/
```
